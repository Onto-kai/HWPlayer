# HWPlayer

**基于 C++、FFmpeg、CUDA/NVDEC 与 OpenGL 的 Windows 多媒体播放器**

HWPlayer 是一个面向 C++
音视频开发学习的桌面播放器项目，主要实践本地媒体文件解析、视频解码、视频帧处理以及
GPU 渲染流程。项目使用 FFmpeg 读取媒体容器和解码视频，结合 CUDA/NVDEC
探索 NVIDIA GPU 硬件解码，并通过 OpenGL 与 GLSL 将视频帧绘制到窗口中。

> 当前项目以 Windows + Visual Studio 2022
> 为主要开发环境。项目仍在持续完善中；本文将现有实现与后续计划分开说明。

## 项目简介

多媒体播放器需要协调媒体容器解析、音视频数据解码、帧数据处理和图形显示等环节。HWPlayer
将这些环节拆分到不同模块中，作为理解 C++ 音视频处理链路和 GPU
视频渲染的实践项目。

项目目前重点关注：

1.  使用 FFmpeg 打开媒体文件并获取流信息。
2.  通过解码器将压缩视频数据转换为可处理的视频帧。
3.  探索 CUDA/NVDEC 硬件视频解码路径。
4.  处理 NV12 视频帧，并通过 OpenGL 纹理和 GLSL 着色器完成画面渲染。
5.  使用队列等模块组织数据传递，为后续完善播放调度和同步机制打下基础。

## 整体处理流程

``` text
本地媒体文件
     |
     v
FFmpeg 打开文件 / 解封装
     |
     v
读取媒体流信息并选择视频流
     |
     v
视频数据包送入解码流程
     |
     v
CUDA / NVDEC 硬件解码（受环境与格式支持情况影响）
     |
     v
获取并处理视频帧（例如 NV12）
     |
     v
OpenGL 纹理 + GLSL 着色器
     |
     v
输出视频画面
```

说明：

-   上图概括了项目的主要视频处理链路，不代表每个步骤都已针对所有格式实现了完整兼容。
-   音频播放、时钟管理、帧同步和 Seek
    后队列刷新等部分仍应以当前代码与实际测试结果为准。
-   硬件解码是否真正启用，需结合 FFmpeg
    构建选项、显卡能力、驱动版本和运行日志确认。

## 关键技术说明

### 1. FFmpeg 媒体处理

FFmpeg
提供媒体容器解析、流信息获取和编解码相关接口。播放器需要区分容器、流、压缩数据包与解码帧等概念：

-   **容器（Container）**：例如
    MP4、MOV、MKV，用于组织一个或多个媒体流。
-   **媒体流（Stream）**：视频流、音频流及其编码参数。
-   **数据包（Packet）**：封装或编码后的压缩媒体数据。
-   **解码帧（Frame）**：解码器输出、供后续显示或播放处理的数据。

理解这些对象的生命周期、时间戳和错误处理，是进一步实现稳定播放器的基础。

### 2. CUDA / NVDEC 硬件视频解码

项目接入 NVIDIA 硬件解码路径，目的是减少 CPU
执行视频解码工作的负担。实际效果与视频编码格式、分辨率、显卡能力、驱动及
FFmpeg 的硬件加速支持有关。

需要注意：**使用了 CUDA/NVDEC
并不自动意味着整个播放链路实现了零拷贝**。如果解码帧需要从 GPU
显存传回主机内存，再上传为 OpenGL
纹理，仍会产生数据传输开销。后续可以进一步研究 CUDA 与 OpenGL
资源互操作、硬件帧上下文及 GPU 侧数据共享。

### 3. NV12 与 OpenGL 渲染

NV12 是常见的 YUV 4:2:0 半平面像素格式，包含：

-   **Y 平面**：每个像素对应一个亮度采样。
-   **UV 平面**：U、V
    色度分量交错存储，采样分辨率通常为亮度平面的四分之一（按像素数量计算）。

项目使用 OpenGL 纹理承载 Y、UV 平面数据，并由 GLSL
着色器参与视频画面生成。此方案可以帮助理解视频像素格式、纹理采样和 GPU
渲染之间的关系。

渲染结果可能受 YUV/RGB
转换矩阵、色彩范围、色彩空间和纹理尺寸影响；对于不同来源的视频，后续可以补充更完整的色彩信息处理。

### 4. 队列与模块化设计

项目中包含数据包队列、帧队列和环形缓冲区等模块。此类结构可用于解耦生产者和消费者，避免解封装、解码、音频处理和显示环节直接耦合。

队列设计需要重点关注：

-   互斥锁与条件变量的正确使用。
-   队列为空、队列已满以及退出时的处理。
-   Seek 或停止播放时旧数据的清理。
-   解码线程、渲染线程之间的生命周期与资源所有权。
-   缓冲策略对延迟、卡顿和内存占用的影响。

## 编译与运行

### 1. 获取代码

``` bash
git clone https://github.com/Onto-kai/HWPlayer.git
cd HWPlayer
```

### 2. 安装依赖

安装 Visual Studio 2022，并确保包含"使用 C++
的桌面开发"工作负载。然后准备与项目配置匹配的 FFmpeg、SDL2、GLAD 和 CUDA
开发环境。

依赖版本需要与项目文件中的头文件目录、库目录及链接依赖保持一致。若出现头文件找不到或链接错误，请优先检查项目属性中的路径和库名。

### 3. 使用 Visual Studio 编译

1.  使用 Visual Studio 2022 打开 `hwplayer_win.sln`。
2.  将解决方案配置选择为 `Debug` 或 `Release`。
3.  将平台选择为 `x64`。
4.  检查第三方依赖路径及链接器配置。
5.  生成解决方案，并根据输出窗口定位编译或链接错误。

### 4. 准备运行时依赖

运行程序前，确保程序所依赖的 DLL 可被系统找到。可采用以下方式之一：

-   将所需 DLL 放到可执行文件所在目录；
-   将相应 DLL 所在目录加入 `PATH`；
-   使用项目配置或部署脚本统一管理运行时依赖。

还需确保着色器文件位于程序能够访问的路径。当前程序使用相对路径
`shaders/vertex.glsl` 和
`shaders/fragment.glsl`，因此建议从仓库根目录启动程序，或在 IDE
中将"调试工作目录"设置为仓库根目录。

## 运行示例

在仓库根目录打开终端，传入本地视频文件路径：

``` bat
x64\Debug\hwplayer_win.exe "D:\Videos\demo.mp4"
```

如果可执行文件生成在其他目录，请将命令中的路径改成实际生成路径。视频文件路径包含空格时，需要使用双引号。

也可以在 Visual Studio 中配置调试参数：

1.  右键项目，打开"属性"。
2.  进入"配置属性 → 调试"。
3.  将"命令参数"设置为待播放视频的完整路径，例如：

``` text
"D:\Videos\demo.mp4"
```

4.  将"工作目录"设置为包含 `shaders` 目录的仓库根目录。
5.  启动调试。

## 常见问题

### 1. 找不到 `vertex.glsl` 或 `fragment.glsl`

检查运行时工作目录。着色器采用相对路径加载时，程序的当前工作目录会影响文件查找。建议将工作目录设为仓库根目录，并确认
`shaders` 文件夹存在。

### 2. 找不到 FFmpeg、SDL2 或 CUDA 相关头文件

检查 Visual Studio 项目属性中的附加包含目录，并确认对应 SDK
已正确安装。头文件目录必须指向实际存在的目录。

### 3. 出现 `LNK2019`、`LNK2001` 等链接错误

检查附加库目录和附加依赖项是否与当前架构、编译配置及依赖版本匹配。x64
项目应链接对应的 x64 库，Debug/Release 也需遵循第三方库的要求。

### 4. 程序启动时提示缺少 DLL

确认 FFmpeg、SDL2 及其他运行时依赖 DLL 可被加载。可以将必要 DLL
放在可执行文件旁，或配置正确的 `PATH`。请遵守各依赖项目的分发许可要求。

### 5. 硬件解码不可用或初始化失败

确认显卡和驱动支持目标视频编码格式，且所使用的 FFmpeg
构建包含所需硬件加速支持。不同 FFmpeg 构建的 CUDA/NVDEC
支持可能不同；应结合实际错误日志排查，不能仅凭安装了 CUDA
就断定硬件解码可用。

### 6. 画面颜色异常

检查输入帧像素格式、NV12 的 Y/UV
平面布局、纹理格式、纹理尺寸以及着色器中的 YUV 到 RGB
转换方式。色彩范围和转换矩阵不匹配也可能导致画面偏色或对比度异常。
